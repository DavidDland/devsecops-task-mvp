# DevSecOps Task Tracker MVP

A deliberately small FastAPI project for practicing:

- Git
- automated tests
- Docker
- container images
- Kubernetes
- health checks
- replicas / desired state
- later: Helm, ArgoCD, Terraform, Ansible, CI/CD, security scanning

## What the app does

The API stores tasks in memory and supports:

- `GET /` - basic app info
- `GET /health` - health check
- `GET /tasks` - list tasks
- `POST /tasks` - create task
- `PATCH /tasks/{id}` - toggle completion
- `DELETE /tasks/{id}` - delete task
- `GET /docs` - Swagger UI generated by FastAPI

> Important: tasks are stored only in memory. Restarting the application clears them.
> This is intentional for the MVP.

## 1. Run locally

Create a virtual environment:

```bash
python -m venv .venv
```

Activate it.

macOS/Linux:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Install dependencies:

```bash
pip install -r requirements-dev.txt
```

Run tests:

```bash
pytest
```

Start the app:

```bash
uvicorn app.main:app --reload
```

Open:

```text
http://localhost:8000/docs
```

## 2. Try the API

Create a task:

```bash
curl -X POST http://localhost:8000/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Learn Kubernetes"}'
```

List tasks:

```bash
curl http://localhost:8000/tasks
```

Health check:

```bash
curl http://localhost:8000/health
```

## 3. Dockerize it

Build the image:

```bash
docker build -t task-mvp:1.0 .
```

Run it:

```bash
docker run --rm -p 8000:8000 task-mvp:1.0
```

Then visit:

```text
http://localhost:8000/docs
```

## 4. Deploy to Kubernetes

For a local cluster such as Docker Desktop Kubernetes, Minikube, or Kind,
make sure the image is available to the cluster.

Apply the manifests:

```bash
kubectl apply -f k8s/deployment.yaml
kubectl apply -f k8s/service.yaml
```

Check the deployment:

```bash
kubectl get deployments
kubectl get pods
kubectl get services
```

Port-forward the service:

```bash
kubectl port-forward service/task-mvp-service 8080:80
```

Then visit:

```text
http://localhost:8080/docs
```

## 5. Observe Kubernetes desired state

The Deployment asks for:

```yaml
replicas: 2
```

Check the pods:

```bash
kubectl get pods
```

Delete one:

```bash
kubectl delete pod <pod-name>
```

Then immediately run:

```bash
kubectl get pods
```

Kubernetes should create a replacement pod because the desired state is two replicas.

This is one of the most important Kubernetes concepts to understand.

## Important MVP limitation

Each pod has its own in-memory task list.

With two replicas, one request may reach Pod A and another may reach Pod B.
That means task data can appear inconsistent.

This is actually useful for learning because it naturally motivates the next architectural step:

```text
Pods -> shared database
```

A later version can add PostgreSQL so all replicas share persistent state.

## Recommended learning sequence

1. Run locally.
2. Read `app/main.py`.
3. Run the tests.
4. Build the Docker image.
5. Run the container.
6. Deploy it to Kubernetes.
7. Delete a pod and watch Kubernetes restore desired state.
8. Scale from two replicas to four.
9. Convert the Kubernetes YAML to a Helm chart.
10. Put the Helm configuration in Git and use ArgoCD.
11. Add a CI/CD pipeline.
12. Add image/dependency security scanning.
13. Add Terraform and Ansible only after the deployment flow makes sense.
